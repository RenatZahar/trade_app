## Договор о типах тестов

- `unit_smoke`: быстрые проверки без Redis, Bitcoin Core и большой БД.
- `integration_live`: сценарии с реальными внешними сервисами и реальными данными.
- `debug scripts`: одноразовые исследования, которые не обязаны проходить всегда и не входят в обязательный pytest-контур.

## Краткая теория

- Тестовый фундамент не начинается с полного покрытия проекта. Он начинается с воспроизводимого способа запускать маленький, стабильный набор тестов из одной точки.
- Для текущего проекта первый полезный шаг:
  - не тащить в тесты живые Redis / Bitcoin Core / Flask-runtime;
  - сначала покрыть стабильные границы: `entrypoint`, runtime-config parsing и run-tracking.
- Unit test проверяет маленький кусок поведения без внешних зависимостей.
- Smoke test проверяет, что базовый сценарий или интерфейс проекта вообще собирается и работает в ожидаемой форме.

## Предварительный диагноз

- В корне проекта пока нет `pytest.ini`, `tests/` и `conftest.py`, поэтому test discovery не оформлен как часть инженерного контура.
- Текущие файлы в `modules/tests` больше похожи на исторические helper-заготовки, чем на стабильный regression suite.
- Часть модулей проекта сильно завязана на внешние процессы и runtime-окружение, поэтому для старта важно не пытаться тестировать все сразу.
- Самые безопасные и полезные первые кандидаты:
  - `main.py` как CLI entrypoint;
  - `modules/logger/run_tracker.py` как P0-слой run metadata;
  - `settings/runtime.py` как parsing runtime-paths из env.

## Командная памятка

Быстрые smoke/regression тесты без Redis, Bitcoin Core и большой БД:

```powershell
python -m pytest tests\unit_smoke -q
```

Live/integration тесты с реальными сервисами и данными:

```powershell
python -m pytest tests\integration_live -q
```

Точечный запуск live-сравнения SQL/BTC через `main.py`:

```powershell
python main.py test downloaded-from-btc-data 3 1
```

Точечный запуск только smoke-теста индексов:

```powershell
python -m pytest tests\unit_smoke\test_sql_indexes_smoke.py -q
```
