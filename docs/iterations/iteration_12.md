# Iteration 12 - Theory review and knowledge check

## Тема

Повтор теоретических знаний и проверка понимания перед следующими крупными
архитектурными задачами.

## Статус

Planned

## Контекст

- К этому моменту в проекте уже пройдены P0/P1-темы программы Junior+:
  запуск, конфигурация, логирование, ошибки, тестовый фундамент,
  детерминизм и базовая инженерная гигиена.
- Перед переходом к сложным темам вроде сравнения pipeline с legacy notebook,
  SQL performance review, agentic-ready контуров и портфолио-упаковки нужно
  отдельно проверить, что базовые инженерные понятия закреплены.
- Подробный промт для проверки знаний будет написан отдельно перед стартом
  итерации.

## Цель итерации

Сделать учебную паузу без крупной разработки:

- повторить теорию, которая уже всплывала в предыдущих итерациях;
- проверить понимание ключевых инженерных понятий на примерах текущего проекта;
- выявить пробелы, которые мешают безопасно двигаться дальше;
- зафиксировать короткий список тем, которые нужно подтянуть перед следующими
  архитектурными изменениями.

## Предварительные темы для повтора

- Git workflow:
  - ветки итераций;
  - merge в `main_branch`;
  - разница между локальным и удаленным состоянием;
  - безопасная синхронизация без потери локальных изменений.
- Python runtime:
  - imports;
  - исключения и propagation;
  - сигнатуры функций;
  - `*args` / `**kwargs`;
  - side effects и границы функций;
  - `with`, context manager и `@contextmanager`;
  - зачем в context manager используется `yield`: код до `yield` выполняется
    перед телом `with`, тело `with` выполняется в точке `yield`, а код после
    `yield` выполняется после блока или при обработке ошибки.
- CLI и orchestration:
  - `argparse`;
  - top-level сценарии;
  - service-команды;
  - почему entrypoint должен быть тонким.
- Логирование и наблюдаемость:
  - run id;
  - stages;
  - progress;
  - duration;
  - что должно попадать в лог, а что лучше держать в debug-артефактах.
- Тесты:
  - unit vs smoke vs integration-live;
  - fixture;
  - regression test;
  - почему быстрый зеленый контур важнее полного покрытия на старте.
- SQL basics для проекта:
  - таблицы и индексы;
  - `JOIN` / `EXISTS`;
  - `GROUP BY`;
  - WAL / SHM;
  - `VACUUM`;
  - `ANALYZE`;
  - почему bulk maintenance требует design review.
- Детерминизм экспериментов:
  - seed;
  - commit hash;
  - параметры запуска;
  - data snapshot;
  - metadata запуска.

## Формат итерации

Финальный формат будет задан отдельным промтом перед стартом.

Ожидаемый рабочий формат:

- короткие вопросы по теории;
- вопросы на чтение кода проекта;
- маленькие практические задания без тяжелых изменений;
- фиксация пробелов и next steps в конце.

## Границы итерации

В этой итерации не делаем:

- крупные refactor-задачи;
- массовые SQLite maintenance-операции;
- перенос pipeline на новую модель данных;
- сравнение текущего pipeline со старым notebook flow;
- портфолио-упаковку проекта.

Эти задачи остаются в следующих итерациях.

## Definition of Done

- Составлен и пройден промт проверки знаний.
- Зафиксированы сильные зоны и пробелы.
- Для каждого пробела есть короткое следующее действие:
  повторить тему, разобрать участок кода, сделать маленькое упражнение или
  перенести задачу в будущую итерацию.
- Обновлен roadmap, если проверка показала, что порядок следующих итераций нужно
  скорректировать.
