# Диагностика репозитория и учебная программа (junior+ → agentic systems)

## Краткий диагноз текущего состояния

Приоритеты оценены в формате `P0 → P1 → P2`.

### P0 — воспроизводимость (run/config/logs)
- В проекте есть единый `main.py` и модуль конфигурации `config.py` с `.env`-переменными.
- В `main.py` рабочие сценарии переключаются флагами (`MAIN_TEST`, `FLASK_TEST`, `MOVE_TXS` и т.д.), что удобно для ручного запуска, но пока затрудняет предсказуемые repeatable run-сценарии.
- Логирование уже централизовано через `setup_logging`, но сейчас используется в основном консольный вывод.

### P1 — инженерия и тесты
- Есть папка `modules/tests`, но это скорее набор скриптов/проверок, а не регулярный тестовый контур с единым запуском.
- Видно смешение инфраструктурных и доменных задач в entrypoint (`main.py`), из-за чего сложнее локально отлаживать отдельные шаги конвейера.

### P2 — прочее
- Есть прикладные модули (парсер, SQL-утилиты, обучение моделей, Flask), то есть хорошая база для постепенной модульной стабилизации без крупных перестроек.

## Учебная программа (8 итераций)

1. **Итерация 0 (подготовительная): VSCode-окружение и рабочий контур проекта**
   - Цель: убрать «шум» общей папки и сделать воспроизводимую ежедневную рабочую среду.
2. **Итерация 1: Reproducible run profile**
   - Цель: зафиксировать 2–3 безопасных сценария запуска (диагностика, обновление данных, обучение).
3. **Итерация 2: Минимальный тестовый контур**
   - Цель: единый запуск smoke-check + 1–2 стабильных теста на критические функции.
4. **Итерация 3: Конфигурация и валидация `.env`**
   - Цель: ранний fail-fast при некорректных переменных окружения.
5. **Итерация 4: Наблюдаемость и логирование**
   - Цель: стандартизировать ключевые события пайплайна (start/stop/error/duration).
6. **Итерация 5: Работа с SQL-операциями без изменения SQL-схемы**
   - Цель: безопасные обёртки и проверки производительности на уровне Python-слоя.
7. **Итерация 6: Базовый quality gate для CI (локально сначала)**
   - Цель: единая команда проверки перед коммитом.
8. **Итерация 7: Введение в agentic patterns на текущем проекте**
   - Цель: небольшой orchestrator-паттерн для автономного пайплайна с ограничениями.

## Итерация 0 (ваш запрос): VSCode-перенастройка

### Тема и цель
**Тема:** Изоляция рабочего контекста проекта в VSCode.

**Цель:** запускать проект из отдельного workspace-файла с преднастроенными `settings`, `tasks`, `launch`, чтобы не зависеть от «общей» папки и ручных кликов.

### Где применяем
- `trade_app.code-workspace`

### План изменений
1. Создать workspace-файл проекта.
2. Задать локальные исключения поиска/индексации тяжёлых артефактов (`data/models`, `project_clean.zip`).
3. Добавить базовые задачи (`tasks`) для:
   - проверки окружения,
   - запуска `main.py`,
   - запуска модуля тестов.
4. Добавить launch-конфигурации для дебага `main.py`.

### DoD итерации 0
- Проект открывается через `trade_app.code-workspace`.
- В VSCode доступны задачи запуска без ручной правки путей.
- Отладка `main.py` запускается из workspace.
- Поиск/индексация не перегружены бинарными/модельными артефактами.

### Портфолио-артефакт итерации 0
- `trade_app.code-workspace` как воспроизводимый «рабочий профиль» проекта.
