# Windows 11 + VSCode: перенос проекта и новое окружение

## Короткий ответ на ваш вопрос
Да, логика правильная:
1. Подготовить адекватный `requirements.txt`.
2. Перенести папку проекта в отдельную директорию.
3. Создать новое `venv` и установить зависимости.

Git при этом не ломается: вся история в папке `.git`, она переедет вместе с проектом.

## Детальный порядок (безопасный)

### Шаг 0. Проверить чистоту репозитория
```powershell
git status
```
Если есть незакоммиченные изменения — закоммитьте их до переноса.

### Шаг 1. Перенести проект в отдельную папку
Пример: `D:\projects\trade_app`.

После переноса:
```powershell
cd D:\projects\trade_app
git status
```
Git увидит тот же репозиторий, если папка `.git` осталась внутри проекта.

### Шаг 2. Создать новое окружение
```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### Шаг 3. Заполнить `.env`
```powershell
copy .env.example .env
```
Заполните как минимум RPC-переменные.

### Шаг 4. Открыть проект через workspace
Откройте в VSCode файл `trade_app.code-workspace`.

## Что будет с Git после переноса
- **Коммиты/ветки/история сохранятся** (это в `.git`).
- `origin`/remotes сохранятся.
- Может измениться только абсолютный путь на вашем диске (это нормально).
- Если раньше `venv` был в общей папке Python, Git это не волнует — вы создадите новый локальный `.venv` рядом с проектом.

## Нужно ли ставить все зависимости?
- Для полноценного запуска проекта: **да**, ставьте всё из `requirements.txt`.
- Для очень узких задач можно ставить подмножество, но это увеличивает риск внезапных падений при запуске других модулей.
