# Agents and skills: русское пояснение

Статус: пояснение для человека. Агент не должен читать этот файл по умолчанию.
Активные правила лежат в `AGENTS.md` и `.agents/skills/*/SKILL.md`; если перевод
расходится с ними, следовать нужно активным правилам.

## Главная идея

Система инструкций теперь сильнее экономит контекст:

1. агент начинает с `AGENTS.md` и короткого `docs/agent_context.md`;
2. открывает только файлы, прямо нужные для задачи;
3. большие docs, старые итерации, backlog, переводы и сырые логи не читаются по умолчанию;
4. safety для SQLite, больших таблиц, индексов и maintenance остается жестким.

`docs/codex_cost_control.md` теперь справочный файл для человека, а не обычный
файл первого чтения агента.

## Роли файлов

- `AGENTS.md` - короткий маршрутизатор: entry check, task modes, safety triggers,
  validation, запреты.
- `docs/agent_context.md` - минимальный текущий контекст: активная итерация,
  ветка, следующий шаг, проверки и границы.
- `docs/active_work_plan.md` - только текущие приоритеты; читать, когда задача
  действительно зависит от приоритетов.
- `docs/codex_cost_control.md` - справка по экономии контекста и starter для
  нового чата; не читать автоматически.
- `.agents/skills/*/SKILL.md` - подробные workflow, которые подключаются только
  по триггеру задачи.

## Skills

- `data-pipeline-safety-check` - обязателен для SQLite, bulk data, индексов,
  `VACUUM`, `ANALYZE`, maintenance и долгих DB-операций. Сначала design review,
  потом пользователь выбирает вариант, только затем mutation/expensive scan.
- `discuss-plan-execute` - для крупных, неоднозначных, архитектурных,
  исследовательских и multi-file задач. Маленькие локальные правки делаются без
  этой церемонии.
- `review-python-module` - review-only режим: сначала findings с file/line,
  без редактирования файлов.
- `iteration-workflow` - старт/продолжение/закрытие итераций, ветки, commit,
  push, merge. README impact check больше не является автоматическим для каждой
  финализации; он нужен при closeout, явном пользовательском запросе или
  очевидном изменении публичного поведения.
- `iteration-handoff` - перенос состояния между чатами. Писать handoff в
  iteration doc только по согласию, явному запросу или когда иначе потеряется
  важное состояние.
- `experiment-protocol` - для экспериментов, конкурирующих подходов,
  performance-гипотез и временного experimental-кода. Durable record нужен
  только если эксперимент создает знание на будущее, меняет направление,
  runtime behavior или data layout.

## Что важно помнить пользователю

- Если нужно максимально надежное закрытие итерации, явно попроси:
  "закрой итерацию с README impact check и обновлением Work Status".
- Если нужен перенос в новый чат, явно попроси:
  "сделай iteration handoff".
- Если нужен широкий аудит, явно скажи "сделай broad audit"; иначе агент будет
  смотреть только ближайший контекст.
- Если работа касается SQLite/large data/indexes/maintenance, агент должен
  остановиться на design review и ждать выбора варианта.
- Если хочешь сохранить эксперимент как проектное знание, попроси создать или
  обновить record в `docs/experiments/`.

## Актуализация переводов

Файлы `*_translate_ru.md` обновляются только когда задача явно меняет проектные
инструкции или документацию. Они не являются источником истины для агента.
